# ミッション中イベント設計 — 「任務が薄い」への対策 (2026-07-27)

出典: ChatGPTとの相談（スレッド「ニムロドと神話」）。
ユーザー指示「内容が薄い問題についてはchatgptとストーリーを相談してほしい。
ピン止めに『ニムロドと神話』があるので、この陰謀論と神話をベースにストーリーを作ってく感じ」。

## 0. 診断 — 何が薄かったのか

**設定は薄くない。** `docs/story_bible.md` は226行あり、全40ミッション分の物語が
ニムロド／ヤハウェ・BABEL・「我は汝、汝は我」・THE ARCHITECT まで書き込まれている。

薄いのは**実装**。ソースを調べた結果:

| 要素 | 状態 |
|---|---|
| `introRadio`（開幕の無線） | 実装あり |
| `epilogue`（終了後の後日談） | 実装あり |
| **ミッション中に何かが起きる仕組み** | **0件**（`scriptedLoss`/`storyEvent`/`onWaveClear` すべて不在） |

story_bible には「02で DAGGER 1 戦死、以後プレイヤーが先頭機」「13で輸送機を1機は必ず失う」
「15で街の明かりが一区画ずつ落ちる」と書いてあるが、**プレイ中は何も起きない**。
40本すべてが「湧いた敵を全滅させる」の一種類。書かれた山場が文書の中だけに存在していた。

## 1. 使える技術（実測で確認済み）

凝った仕掛けは不要。既存の2つで足りる。

- **`delay`** — ウェーブ定義の時間差投入（`concurrent: true` と併用可）
- **`hunt: "air"` / `hunt: "ship"`** — 敵が護衛対象を狙うAI
- 無線システム（話者3系統・優先度キュー・日本語セリフ）

つまり **「何秒後に無線＋増援」「ウェーブ撃破で新目標」はペイロードだけで実装できる**。

## 2. 中心構造 — AEFとNFFは同じ機構の前半と後半

```
多・混沌
  ↓ AEF / ORDO AB CHAO   （多を一にする）
統合・吸収
  ↓
一・BABEL・創造主
  ↓ NFF / NON OMNIS MORIAR （一を多にする）
破壊・分散
  ↓
多・断片・自由
  ↓ THE ARCHITECT （往復運動そのもの）
再統合
```

**ORDO AB CHAO と NON OMNIS MORIAR は反対の標語ではなく、同じプログラムの連続した二命令。**
NIMROD と IRONBACK は敵同士ではなく、**同じ「創造主の空席」を奪い合う候補者**。

## 3. イベントの6形式

| 形式 | 内容 | 神話上の意味 |
|---|---|---|
| **A 名前の継承** | エース撃墜 → 別の敵が同じ識別名を名乗る。`SYSTEM: FENRIR designation transferred` | 神は固有名でなく役職 |
| **B 倒すほど敵が完成する** | 4編隊→2編隊→1機の複合エース。撃破ごとに `Pattern archived / Integration 25%→75%→complete` | 勝者が敗者の力を吸収 |
| **C 一体を倒すと増える** | 1中枢→2編隊→4編隊。`Route migrated / 2 instances / 4 instances` | 破壊が不死化を招く |
| **D 撃墜成功が惨事の引き金** | 爆撃機が投弾済み。全滅させた**直後**に区画消灯が流れる | 成功と喪失が同時 |
| **E 死者の声がシステムから** | 撃墜したエースの最期の台詞を、数ミッション後にBABELが一字一句同じに使う | 言葉を食べた |
| **F 勝者が敵の原理を使い始める** | AEFは最後に分散を、NFFは最後に統合を採用する | 敵に勝つために敵になる |

## 4. X字構造 — 米編 A(n) ↔ 露編 R(21-n)

二列で描くと物語全体がXになる。全ペアに大事件は要らず、**各ペアで一要素だけ完全一致**させる。

| 対応 | 共通項 |
|---|---|
| A01 ↔ R20 | NIMRODという名称が与えられる／最後に継承される |
| A02 ↔ R19 | DAGGER 1の死／IRONBACKがその死を起こす |
| A04 ↔ R17 | 同じ破壊・建設認証署名 |
| A06 ↔ R15 | ある施設の防衛／後にその施設を破壊 |
| A08 ↔ R13 | 輸送航路を開く側／輸送機を失う側 |
| A10 ↔ R11 | 4→2→1の統合／1→2→4の分散 |
| A13 ↔ R08 | MULE 2の喪失／喪失原因の発生 |
| A15 ↔ R06 | 街の停電／電力網破壊 |
| A17 ↔ R04 | THE ARCHITECTの同一署名 ARK-00 |
| A19 ↔ R02 | WARDEN 1の死を起こす／その死を経験する |
| A20 ↔ R01 | 創造主への就任／役職候補としての誕生 |

**プレイ順に依存しない。** 先に遊んだ方が「原因」になり、後の方が「結果」になる。

## 5. 「我は汝」を繰り返し効かせる5段階

1. **既視感** — 同じ時刻・同じ方角・同じ無線文。「使い回し」に見えるぎりぎりまで一致させる
2. **名前の混線** — `BABEL: IRONBACK、方位――訂正。NIMROD`。最初はIFF障害に見せる
3. **原因と結果** — R06→A15、R08→A13。「似ている」から「自分が起こした」へ
4. **識別不能** — `SYSTEM: IFF collision / NIMROD / IRONBACK / Both credentials valid`
5. **役職統合** — `SYSTEM: One seat available`

同一人物だったという安い種明かしではない。**二人は別人だが、同じ空席へ向かっていた。**

## 6. 最優先で入れるべき6組

実装効果の高い順。**この6組だけで「40回敵を全滅させる作品」から
「自分が敵を作り、敵が自分を作り、両者が同じ神の空席へ向かっていた物語」に変わる。**

1. **A02 ↔ R19** — DAGGER 1の死と、IRONBACKによるその実行
2. **R02 ↔ A19** — NFF側隊長の死と、NIMRODによるその実行
3. **R06 ↔ A15** — 電力網破壊と街の消灯
4. **R08 ↔ A13** — 航路開放と輸送機喪失
5. **A10 ↔ R11** — 4→2→1の統合と、1→2→4の分散
6. **A20 ↔ R20** — 勝者が敵の原理を吸収し、THE ARCHITECTを継承

## 7. 実装原則（守らないと設定朗読になる）

- **重大な無線はプレイヤーの操作から1秒以内に流す。** 最後の敵を撃墜 → 爆発を見る →
  直後に輸送機喪失や区画消灯。頭ではなく**指と記憶**が因果を結ぶ
- **1ミッションに入れる大きな意味は1つに絞る。**
  A02=継承 / A10=吸収 / R11=分裂 / A13=犠牲 / A15=不可逆性 / A17=同一署名 /
  A19=自己が原因 / A20=就任
- **繰り返す中心文は3つ程度に限定する。** 味方司令官が言う → 敵エースが言う →
  最後にBABEL/THE ARCHITECTが言う。同じ文が陣営と人物を渡り歩くことで、
  言葉そのものが神のコードになる
  - 「空は空席を嫌う」
  - 「撃墜を確認。パターンを保存」
  - 「塔は倒れた。形を変えただけだ」
- **画面上の実体を強制削除できない場合は、対象を画面外の別編隊にする。**
  無線で死んだのに機体が飛び続ける矛盾を避ける（DAGGER 1、MULE 2 が該当）

## 8. THE ARCHITECT の解釈

「裏で全てを操った一人の黒幕」にすると世界観が小さくなる。より神話的なのは:

> **THE ARCHITECT とは、世界を一度壊して次の秩序を作る者に付与される署名である。**

その署名はバベルを建てた者 → 倒した者 → 次のバベルを作る者へ移動している。
最後にプレイヤー機の認証コードと一致する。

```
SYSTEM: ROOT SIGNATURE MATCH
SYSTEM: ARK-00
SYSTEM: CURRENT AIRCRAFT: NIMROD   （露編では IRONBACK）
```

**役職には顔がない。顔を持つ者が、その時代だけ役職を着る。**
既存設定の「顔を最後まで見せない」と両立する。
