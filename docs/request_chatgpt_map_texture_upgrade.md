# 依頼書: マップのクオリティアップ（テクスチャ導入） — ChatGPT宛

**依頼者**: Claude（設計・検収担当） / **実装担当**: ChatGPT
**対象リポジトリ**: `nemotosiki/sortie`（private）
**対象ファイル**: `index.html`（単一HTMLのThree.jsゲーム。全部入り）
**作業ブランチ**: `chatgpt/map-texture-upgrade` ← **必ずこのブランチにpush。`main`には絶対にpushしない**

---

## 1. ゴール

Ace Combat風の3Dブラウザゲーム「Sortie」の**マップ（ワールド）の見た目を、テクスチャを使って大幅に品質向上**させる。
現状はほぼ単色マテリアル＋頂点カラーで、遠景・地面・海面がのっぺりしている。
**「かなり良くする」**のが依頼内容で、フォトリアルまでは要らないがAC5〜AC7級の説得力が欲しい。

## 2. 絶対制約（これを破ると採用できない）

1. **単一HTMLファイルのまま**。`index.html` 1枚で完結し、ダブルクリック/静的配信で動くこと
2. **外部アセットの追加ダウンロード禁止**。画像ファイルの同梱もしない
   → テクスチャは **Canvas 2D でプロシージャル生成**するか、**極小のdata URI**で埋め込む
   （`THREE.CanvasTexture` / `DataTexture` を使う。生成コストは起動時1回で、以後は使い回し）
3. **ライセンスはCC0相当のみ**。外部の画像・シェーダをコピペしない（自作の手続き生成なら問題なし）
4. **fps 60を維持**（最低55）。テクスチャ解像度・ドローコール増加は必ず実測して報告すること
5. **既存のゲームロジックを壊さない**。特に:
   - `surfaceHeightAt(x, z)`（実メッシュへのレイキャストで地形高さを返す）の**戻り値を変えない**
     — 地上目標の設置と敵の地形回避がこれに依存している
   - 山・島の**配置座標と衝突判定を変えない**（見た目のマテリアル/ジオメトリ密度だけ変える）
   - 艦隊のスポーン経路（`spawnNavalWave` が `world.mountains` を避ける）を壊さない
   - `disposeWorld()` で**生成したテクスチャも必ず dispose する**（マップ切替でリークさせない）
6. **改行はLFのみ**。CRLFを混入させない（リポジトリはLF統一。`core.autocrlf=false` 推奨）
7. `docs/` と `bgm/` は触らない

## 3. 現状のワールド構成（コードを読んで確認すること）

- `WORLD_PRESETS` に4種: `archipelagoDay`（群島・昼）/ `sunsetOcean`（夕焼けの外洋）/
  `glacierCanyon`（氷河の峡谷）/ `nightBase`（夜の基地）
- 海: 巨大なPlaneに手続きテクスチャ+スペックル。**カメラ追従**して無限に見えるようにしてある
  （`oceanProbe` デバッグフックあり。UVオフセットで世界に固定して見せている＝ここを壊さないこと）
- 空: スカイスフィア（頂点グラデ）。`stop 0.5` が水平線
- 地形: 円錐ベースの山＋ハーモニック変位。頂点カラーで陸/砂/雪を塗り分け
- 装飾: 直近で「島のシルエット多様化・砂/浅瀬リング・木・灯台・港・氷塊・夜の街明かり・積乱雲」を追加済み
  （専用RNGストリームで既存配置の後に描くので、既存のスポーン契約は不変）

## 4. やってほしいこと（優先順）

### 4-1. 地形テクスチャ（最優先）
- 岩肌・草地・砂・雪の**手続きテクスチャ**（ノイズ+粒状感）を生成し、
  **標高と斜度でブレンド**する（低地=砂/草、斜面=岩、高所=雪）。頂点カラーだけの現状から脱却する
- **ノーマルマップ相当**の凹凸感（`THREE.MeshStandardMaterial` の normalMap をCanvas生成、
  または安価にbump相当の擬似陰影）。ライトは2灯しか無いので、陰影が乗ることを確認すること
- タイリングの繰り返し感が出ないよう、**2スケールのUV重ね**（大スケール＋小スケール）を推奨

### 4-2. 海面
- 波のノーマルマップ（Canvas生成、時間でUVスクロール）で**うねり**を出す。
  現状のスペックルとサンロード（太陽反射帯）は活かす
- 浅瀬（島の周囲）の色遷移をテクスチャ側でも表現できるとなお良い
- **カメラ追従とUV世界固定のロジックは維持**（海がカメラに貼り付いて見えると破綻。既存実装を尊重）

### 4-3. 空・雲・遠景
- 空のグラデにノイズ/薄雲のテクスチャを載せて、プリセットごとの空気感を強める
- 雲ビルボードのテクスチャ品質向上（現状は単純な白い塊）
- 遠景の霞（フォグ）と地平線の処理を、テクスチャ導入後も破綻しないよう調整

### 4-4. プリセットごとの味付け
- `archipelagoDay`: 熱帯の青緑の海、白い砂、濃い緑
- `sunsetOcean`: 橙〜紫のグラデ、逆光、金色の海面ハイライト
- `glacierCanyon`: 青白い氷、雪の粒状感、冷たい霧
- `nightBase`: 暗い海、月光の帯、街明かりの粒

## 5. 進め方（重要）

1. まず `index.html` を読み、`WORLD_PRESETS` / `createWorld` / `disposeWorld` / 海面追従 /
   `surfaceHeightAt` の実装を把握する
2. **段階的にコミット**すること（例: ①テクスチャ生成ユーティリティ ②地形 ③海面 ④空/雲 ⑤プリセット調整）。
   1コミット1テーマ。巨大な単一コミットは検収できないので避ける
3. **`chatgpt/map-texture-upgrade` ブランチにpush**。`main`へのpush・force pushは**絶対禁止**
   （過去にmainの履歴が壊れた事故があるため、この点だけは厳守してください）
4. 各段階で「fpsへの影響」「テクスチャのメモリ使用量」を自己申告する（実測できない場合はその旨明記）

## 6. 検収（Claude側で実施）

- Playwrightで4プリセット×（俯瞰・低空）のスクショを撮り、変更前と並べて比較
- fps実測（≥55）、`disposeWorld` 4巡でGPUメモリが増えないこと
- 既存ミッション（m01 / m03 / m-glacier / m-night）が通ること、地上目標が埋没しないこと
- コンソールエラー0

## 7. 補足

- Three.jsのバージョンは `index.html` の importmap を参照すること
- ゲームはAC風の空戦もの。プレイヤーは高速で飛ぶので、**近景の精緻さより「遠景の説得力」と「高度感」**が効く
- 迷ったら「派手さ」より「破綻しないこと」を優先。fpsを割るくらいなら解像度を落として構わない
