## 0. 最重要: index.html を編集しないでください

このリポジトリには**ペイロード登録方式**が実装済みです（`docs/spec_payload_registry.md` が正本）。
コンテンツ追加は **`payloads/` 配下に新規ファイルを1本足すだけ**で完結します。
`index.html`（約29,000行）には**一行も触れないでください**。

理由: 過去にこのプロジェクトで、単一の巨大ファイルへの分散編集により
既存機能が巻き添えで壊れる事故が複数回起きています。ペイロード方式はそれを
構造的に防ぐために用意されたものです。

### ペイロードの書き方

`payloads/<name>.payload.js` を作り、`register(ctx)` を default export します。

```js
// payloads/enemy_variety_1.payload.js
export default function register(ctx) {
  // ctx.tables で既存定義を読める（コピー元にする）
  const { GROUND_TYPES, HELI_TYPES, MISSIONS } = ctx.tables;

  ctx.addHeliType?.("...", { /* ... */ });   // ← 存在しない場合は §2 の指示に従う
  ctx.addGroundType("...", { /* ... */ });
  // 既存ミッションの改修は §3 を参照
}
```

利用できる登録関数（`payloadContext`、index.html の 9482 行付近に定義）:

| 関数 | 用途 |
|---|---|
| `ctx.addMission(def, { after })` | 新規ミッション追加。`after` で挿入位置指定 |
| `ctx.addAircraft(id, def, { order })` | 機体追加。`order:false` で敵専用（ハンガーに出さない） |
| `ctx.addEnemyProfile(id, def)` | 敵AIプロファイル |
| `ctx.addEnemyMissileProfile(id, def)` | 敵ミサイル |
| `ctx.addAceProfile(id, def)` | 名前付きエース |
| `ctx.addShipType(id, def)` | 艦船 |
| `ctx.addGroundType(id, def)` | 地上目標 |
| `ctx.addWorldPreset(key, def)` | マップ |
| `ctx.tables` | 既存全テーブルの読み取り専用ビュー |

**スキーマ検証あり**: 各テーブルの「既存エントリ全部が持っているキー」が必須項目として
自動チェックされます（`requiredKeysOf`）。既存エントリを `ctx.tables` から読んで
必須キーを埋めてください。重複IDは拒否されます（add-only）。

### 動作確認の方法（index.html を書き換えずに実ゲームで試せる）

```
index.html?payloads=payloads/enemy_variety_1.payload.js
```

このクエリを付けて開くと、あなたのペイロードが実ゲームに読み込まれます。
`tools/inline_payload.mjs` で index.html へ本組みする作業は**こちらでやります**。
あなたは payloads/ にファイルを置くところまでで完了です。

## 2. やってほしいこと A — 地上目標4種の追加

`ctx.addGroundType(id, def)` で**4種追加**してください。
既存10種の定義は `ctx.tables.GROUND_TYPES` から読めます。`samSite` や `aaGun` を
コピー元にして必須キーを全て埋めてください。

方向性（エースコンバット準拠。SEAD/対地攻撃の的として成立するもの）:

1. **自走式対空ミサイル車両（静止配置）** — `samSite` より射程が短く、HPも低い。
   数を置いて面で撃ってくる中間の脅威。`aa` あり
2. **指揮所・通信施設** — 反撃してこないが HP が高く、破壊が任務目標になる建物。
   `radarSite` と `bunker` の中間。`aa: null`
3. **弾薬集積所** — `fuelTank` と同じく誘爆する（`chain` を持つ）が、
   誘爆半径は狭く威力は高い。密集配置で連鎖を狙わせる。`aa: null`
4. **CIWS / 近接防空砲座** — `aaGun` の上位。射程は短いが命中率と発射速度が高く、
   低空で突っ込むと危険。`aa` あり

**要件**:
- 4種のうち**2種は対空攻撃能力を持たせる**こと（`aa` が `null` でない）。
  反撃してこない置物ばかり増やしても戦闘が成立しないため
- HP は既存レンジ（50〜120）から極端に外れないこと。
  参考: fuelTank 50 / aaGun 60 / radarSite 70 / samSite 90 / tank 110 / bunker 120
- `label` は英語（HUD表示に使われます）、`role` は英語の説明文

### 注意: ヘリコプターは今回の対象外です

`HELI_TYPES` は `hind` 1種のみで拡充したいのですが、`ctx` に `addHeliType` が
**存在せず**、`HELI_TYPES` は定義時点で `Object.freeze` されているため、
ペイロードからは追加できません。これは**こちらで登録関数を足す作業が先に必要**なので、
別便で扱います。**今回はヘリに手を出さないでください。**

## 3. やってほしいこと B — ロシア編に地上戦を導入（3ミッション）

**新規ミッションは作らないでください。** 20 vs 20 の対称性を保ちたいので、
**既存のロシア編ミッション3本を改修**して地上目標を追加します。

対象は**こちらで指名します**（あなたが選ばないでください）。
露編は「味方を守る」構図で一貫して設計されているため、**地上目標は
"味方陣地を脅かす侵入者" として置き、任務の性格を変えない**のが原則です。

| 対象 | 現在の任務 | 追加する地上目標 | 位置づけ |
|---|---|---|---|
| **r06** GLACIER SHIELD | 氷河回廊のレーダー網に接近する敵攻撃隊を叩く | samSite ×2, radarSite ×1, **新種の指揮所** ×1 | 敵が谷に先行設置した前進防空拠点。潰さないと回廊を守れない |
| **r08** SCRAMBLE | 夜襲を受けている前線基地から上がって基地上空を掃討 | tank ×3, adTank ×1, **新種のCIWS** ×2 | 基地に取り付いた敵地上部隊。空だけ掃討しても基地は落ちる |
| **r11** SAND WALL | 砂漠航空基地へ向かう敵攻撃隊を基地上空で迎撃 | **新種の自走SAM** ×3, **新種の弾薬集積所** ×2, aaGun ×2 | 敵が砂漠に展開した移動防空陣地 |

§2 で追加する4種の新ユニットが**3本すべてに最低1種は登場する**ように配分してあります。
「テーブルに足したがどこにも出てこない」という置物化を防ぐためです。

**制約**:
- 既存のウェーブ構成・敵機編成・parTime・ブリーフィング文・タイトルは**変更しない**。
  地上目標を**足すだけ**にしてください
- 追加した地上目標は必ず**ミッションの目標としてカウントされる**ようにすること
  （米編 m-glacier / m-night / m-desert の書き方を `ctx.tables.MISSIONS` から読んで真似る）
- 設置座標は必ず地表に接地させること。山腹に置く場合も含め、浮きやめり込みは不可
  （既存ミッションが `surfaceHeightAt` をどう使っているか確認すること）
- **他の17本には触らないでください。** 特に **r20**（撤退戦）はソース中のコメントに
  演出上の意図が明記されているため対象外です

## 4. 絶対に触ってはいけないもの

このプロジェクトの設計原則です。違反した場合は受け入れません。

1. **`index.html` を編集しない**（§0 の理由）
2. **`AIRCRAFT_TYPES` を書き換えない** — 敵と自機で共有しているテーブルです。
   敵を強くしたいなら役割(`role`)かAI練度(`skill`)で調整します
3. **HP に役割倍率・難易度倍率をかけない** — 敵の強さは
   「機体性能 × 役割(ace1.20/elite1.05/line1.00/trash0.75) × AIの賢さ」で表現します。
   役割倍率が効くのは**旋回性能とミサイル発射頻度だけ**です。HPは絶対に対象外
4. **既存の10種の地上目標・5種の艦船・既存ミッションの挙動を変更しない**（追加のみ）
5. **将来のための先回り実装をしない** — 頼んでいない拡張ポイントやスキーマ拡張を
   足さないでください。今回の範囲だけを実装してください
