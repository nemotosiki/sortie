## 全便共通の絶対ルール

これを破った成果物は受け入れません。毎回確認してください。

1. **`index.html` を編集しない。** `payloads/` に新規ファイルを作る。
   `ctx.addMission` / `addAircraft` / `addGroundType` / `addShipType` / `addHeliType` /
   `addWorldPreset` / `addEnemyProfile` / `addEnemyMissileProfile` / `addAceProfile` /
   `ctx.tables` / `ctx.marksTaken` で完結します。
   スキーマ検証と重複チェックは自動で入ります。正本は `docs/spec_payload_registry.md`
   - 例外は §4-B（地形生成）だけ。そこは本体改修が要るので**設計だけ出してもらい、実装はこちらでやります**
2. **`AIRCRAFT_TYPES` の既存エントリを書き換えない**（敵と自機で共有しているテーブル）
3. **HP に役割倍率・難易度倍率をかけない。**
   敵の強さは「機体性能 × 役割(ace1.20/elite1.05/line1.00/trash0.75) × AI練度」で表現し、
   役割倍率が効くのは**旋回とミサイル頻度だけ**。HPは対象外
4. **既存ミッションは追加のみ。** ウェーブ構成・敵編成・parTime・ブリーフィング文・
   タイトルを変更しない
5. **指定したミッション以外に触らない**
6. **頼んでいない先回りの拡張・スキーマ追加をしない**
7. **`main` へ直接 push しない**。指定ブランチのみ
8. **CI足場や検証ログをブランチに含めない**（前回 `.github/workflows/` と
   `_chatgpt_*.txt/json/log` が約4,000行混入しました。捨てました）
9. 動作確認は `index.html?payloads=payloads/<ファイル>.js` で実ゲームに読み込めます。
   本組み（`tools/inline_payload.mjs`）はこちらでやります
10. 日本語のセリフ・blurb は日本語で。HUD/UIラベルと符牒（GRID-A等）は英語のまま

## 第3便 `chatgpt/support-aircraft` — 敵専用機4種

仕様の詳細: `docs/request_chatgpt_support_aircraft_20260727.md`

### なぜやるか（実測）
`AIRCRAFT_TYPES` は26種だが、内訳が **プレイアブル22機 / 敵専用4種**
（bomber=B-52H, uav=MQ-99, transport=C-17, tu95=Tu-95）。
ハンガーに22機並ぶのに敵側の非戦闘機が4種しかない。ACの護衛・迎撃任務は
「戦わないが戦況を作る機体」を軸に組まれているので、ここを厚くすると任務の種類が増える。

### やること
`ctx.addAircraft(id, def, { order: false })` で4種追加。**`order: false` が必須**
（省くとプレイヤーのハンガーに並ぶ）。`ctx.tables.AIRCRAFT_TYPES.transport` と `.bomber` が雛形。

| # | 種別 | HP | 武装 |
|---|---|---|---|
| 1 | 早期警戒管制機 AWACS | 294 | 無し |
| 2 | 空中給油機 Tanker | 294 | 無し |
| 3 | 電子戦機 EW/Jammer | 196 | 無し |
| 4 | 哨戒機 Maritime Patrol | 196 | 無し |

- **HPは98の倍数**（98=自機ミサイル1発ぶん。既存機のコメントに「HP stays on the 98 quantum」）
- **`spw` を付けない**（特殊兵装はプレイヤー専用）
- **排気色で陣営を示す**。西側は青白（`0x8cec..`〜`0x9fd8..`）、ロシアは暖色
  （`0xffb9..`〜`0xffd9..`）。真後ろから見て敵味方が分かるようにという既存規約
- 4種とも非武装（`gunDamage: 0`）。戦う敵は既に25種いるので、
  今回欲しいのは「落とす価値のある的」と「守る価値のある味方」
- `ctx.addEnemyProfile` も必要。`ctx.tables.ENEMY_AI_PROFILES.transport` が雛形

### ミッションへの組み込み（4本・こちらで指名。変更しないこと）

| 対象 | 現在の任務 | 追加内容 |
|---|---|---|
| **m-intercept** BOMBER STREAM | 重爆撃編隊の迎撃 | **AWACS ×1** を敵編隊後方に。撃墜目標に加える |
| **m-swarm** UAV SWARM | 無人機群との乱戦 | **電子戦機 ×1** を混ぜる |
| **r07** EYE OF THE STORM | 嵐に紛れた強行偵察。Tu-95を守る | **哨戒機 ×1** を護衛対象に追加 |
| **r13** CUT THE LINE | 敵輸送隊を1機で抜けて叩く | **給油機 ×1** を撃墜目標に追加 |

### 検収基準
- 新4種が**ハンガーに出てこない**（`window.__game.aircraftCatalog` に含まれない）
- 各HPが98の倍数、`roleProbe` で ace/trash 両方で**HPが同一**
- 指定4本で実際に出現、`missionKeys()` 40本のまま、全40本起動
- `node tools/registry_gate.mjs` 通過、`index.html` のハンクゼロ

## 第4便 `chatgpt/story-events-2` — 残りの因果ペア5組

設計の正本: `docs/story_events_design_20260727.md`（**必ず読む**）

第2便で R06↔A15 を作ったら、同じ要領で残り5組を作ります。
**第2便がマージされてから着手**（ミッション定義が衝突するため）。

| 組 | 内容 | 使う仕組み |
|---|---|---|
| **A02 ↔ R19** | DAGGER 1 の死と、IRONBACK によるその実行 | `delay` で時間差の無線＋増援 |
| **R02 ↔ A19** | NFF側隊長の死と、NIMROD によるその実行。**A19 で R02 と一字一句同じ最期の台詞を流す** | 同上 |
| **R08 ↔ A13** | 航路ビーコンを開ける（任意目標）／輸送機 MULE 2 を失う | `tgt:false` + `mark` |
| **A10 ↔ R11** | 4→2→1 の統合 ／ 1→2→4 の分散 | ウェーブ構成 |
| **A20 ↔ R20** | 勝者が敵の原理を吸収し、THE ARCHITECT を継承 | 最終ウェーブ＋無線 |

### 各組の実装原則（設計文書 §7）
- **重大な無線は操作から1秒以内に流す。** 最後の敵を撃墜 → 爆発 → 直後に結果。
  頭ではなく指と記憶が因果を結ぶ
- **1ミッションに入れる大きな意味は1つに絞る。**
  A02=継承 / A10=吸収 / R11=分裂 / A13=犠牲 / A15=不可逆性 / A19=自己が原因 / A20=就任
- **繰り返す中心文は3つに限定。** 味方司令官が言う → 敵エースが言う → 最後にBABELが言う
  - 「空は空席を嫌う」
  - 「撃墜を確認。パターンを保存」
  - 「塔は倒れた。形を変えただけだ」
- **画面上の実体を消せない場合は、対象を画面外の別編隊にする**
  （無線で死んだのに機体が飛び続ける矛盾を避ける。DAGGER 1、MULE 2 が該当）

### 名前の継承（設計文書 §3 形式A）
エース撃墜後に別の敵が同じ識別名を名乗る。「神は固有名でなく役職」の直接的な表現。
```
COMMAND: 「FENRIR撃墜確認」
HATI:    「違う。落ちたのは機体だけだ」
SYSTEM:  「FENRIR designation transferred」
```
ヨルムンガンド隊（FENRIR/SURTR/HATI/SKÖLL）とアトラス隊
（ATLAS/PROMETHEUS/DAEDALUS/ICARUS）の両方に入れてください。

## 第6便 `chatgpt/map-density` — マップの人工物密度

### なぜやるか（実測値・2026-07-27にこちらで計測）

全8マップを起動して ±9000m の範囲を14×14グリッドでサンプルした結果:

| マップ | 山 | 最高峰 | 陸地率 | 起伏SD |
|---|---|---|---|---|
| desertBasin | 12 | 188m | **6.1%** | 3.4 |
| nightCity | 5 | 213m | 2.0% | 3.1 |
| coastalPlain | 6 | 204m | 2.0% | 4.1 |
| glacierCanyon | 16 | 561m | 0.5% | 2.7 |

| nightBase | 4 | 189m | **0%** | 0 |
| sunsetOcean | 2 | 183m | **0%** | 0 |
| stormOcean | 2 | 192m | **0%** | 0 |

**陸地が最大でも6%、半分のマップは0%。** 「夜市街」も実態は海に島が数個です。
峡谷や市街地を飛ぶAC体験とは別物になっています。

### この便でやること（ペイロードで完結する範囲）
地形そのものの改造は本体改修が要るので**第7便に回します**。この便は
**既存の地形の上に人工物を置いて「人が住んでいる」密度を出す**ことに絞ります。

- 道路網 / 滑走路+エプロン / 橋 / 非目標の建物クラスタ / 港湾クレーン
- **`InstancedMesh` かジオメトリ結合を必須にする**（draw call を増やさない）
- 対象は陸地のある4マップ（desertBasin / nightCity / coastalPlain / glacierCanyon）
- **fps 60 を割らないこと**が絶対条件。割るなら密度を下げる

### 検収基準
- `debug.gpuMemory()` の geometries / textures 増加が、着手前に報告した予算内
- `createWorld` / `disposeWorld` を8回往復して GPU メモリが戻る（リークなし）
- 全8マップで fps 60 以上（`forceWorld` で切り替えて計測）
- 地上ユニットの設置誤差が 0.0000 のまま（`surfaceHeightAt` 回帰）

`window.__game.debug` に多数あります。検証時に便利なもの:

| フック | 用途 |
|---|---|
| `missionKeys()` / `forceMissionCursor(i)` | ミッション一覧・起動（**解禁チェーンがあるので localStorage に記録を仕込む必要あり**） |
| `groundProbe()` / `heliProbe()` / `roleProbe()` / `airframeProbe()` | ユニットの実測（roleProbe と airframeProbe は**ヘリを除外する**） |
| `markProbe()` / `forceMark(mark, n)` | 任意目標の状況・強制設定 |
| `forceDamageEnemy(id, n)` | 実弾なしで撃破 |
| `surfaceHeightAt(x,z)` / `surfaceTopAt(x,z)` | 地表高さ（**移動ユニットは surfaceTopAt に立つ**） |
| `worldPresets()` / `forceWorld(key)` | マップ切替（**プレイ中は false を返して何もしない。メニュー状態で呼ぶこと**） |
| `worldTextureReport()` / `oceanProbe()` / `gpuMemory()` | マップの実測 |
| `checkpointProbe()` / `guardProbe()` | チェックポイント・護衛目標 |
