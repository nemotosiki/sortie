# 敵航空AI・索敵／交戦アルゴリズム再設計計画 2026-08-27

## 1. 目標

敵機が1km前後まで近づかないと戦闘を始めない旧挙動を廃止し、各編隊が
`purpose`に従って広域索敵、目標選択、接敵、交戦継続、再捜索、離脱を行う。
敵数だけを増やさず、既に配置されている部隊が戦場で仕事を続けることで
戦闘密度を上げる。

完了条件は次のとおり。

- M01〜M20の全航空ウェーブが、目的に合った索敵・交戦契約を持つ。
- 通常戦闘機は数km先の接敵を待たず、8〜15km級で脅威を認識する。
- CAP／護衛は広く索敵するが、守備対象を捨てて無限追撃しない。
- INTERCEPTORは高速進入、オーバーシュート判定、離脱、再進入を繰り返す。
- 目標消失、ミサイル回避、味方撃墜後にもAIが停止・旋回固定しない。
- ARCA、白敵、赤TGT、護衛対象、CAS対象、M11 HALOの既存契約を壊さない。
- 静的検査、決定論的シミュレーション、Chrome E2E、既存ミッションE2Eを通す。

## 3. 現行調査で見つかった問題

### 3.1 索敵・接敵距離

- 機体プロファイルの旧`engageRange`は主に720〜1,140m。
- purpose未設定時は今もこの旧距離へフォールバックする。
- 初期ミッションのCAP／ESCORTは`commitRange` 2,000〜3,000mが多く、
  6.5〜13.5km級の戦場に対して短い。
- 「索敵」と「守備圏へのコミット」が同じ距離判定になっているため、敵が
  プレイヤーを把握しているのか、単に待機しているのかを表現できない。

### 3.2 目標選択

- 防御purposeはRAVENと守備点の距離しか見ず、通常僚機やARCAが守備圏へ
  入っても自律反応しない。
- `assignedTargets`がない編隊は全機がRAVENへ集中しやすい。
- hunt対象は毎フレーム最近傍を選び直すため、複数対象・複数攻撃機で
  ターゲットが揺れる余地がある。

### 3.3 状態遷移

- `interceptor`がAGGRESSIVE扱いだけで、離脱・再進入フェーズを持たない。
- ミサイル回避`break`終了時にpurposeを無視して旧1km判定へ戻る。
- 索敵対象を失った後の記憶・最終既知位置・再捜索時間がない。
- CAPの二番機コミット差はあるが、誰を迎撃するかの分担はない。

## 4. 共通知覚モデル

索敵距離と交戦距離を分離する。距離単位はゲーム内m。

| purpose | 基本索敵 | コミット | 離脱／復帰 | 接触記憶 |
|---|---:|---:|---:|---:|
| INTERCEPT / QRA / RELIEF | 14,000 | 任務指定目標へ常時ベクター | 16,000 | 24秒 |
| PINNING | 13,000 | 任務指定目標へ常時ベクター | 15,000 | 20秒 |
| INTERCEPTOR | 16,000 | 任務指定目標へ常時ベクター | 再進入制御 | 28秒 |
| SCREEN | 12,000 | 4,500 | 7,200 | 20秒 |
| ESCORT | 12,000 | 4,200 | 6,800 | 20秒 |
| CAP | 11,000 | 4,800 | 7,600 | 18秒 |
| TOP COVER | 14,500 | 6,500 | 9,500 | 24秒 |
| purposeなし旧任務 | 8,500 | 8,500 | 11,000 | 14秒 |

方針:

- skillは機体性能ではなく、索敵距離補正、目標保持時間、再判断周期へ使う。
- AGGRESSIVE編隊はGCIから任務指定目標を与えられているため、索敵圏外でも
  最終既知位置へベクターする。射撃距離・ロック時間は既存武器契約のまま。
- DEFENSIVE編隊は守備点を中心に索敵し、脅威がコミット圏へ入るまでCAPを
  継続する。コミット後は離脱圏まで追い、越えたら守備点へ戻る。
- 接触を失っても即座に停止せず、接触記憶中は最終既知位置へ向かう。
- 低高度やジャミングの個別補正は、現行ミッション固有ルールを壊さない範囲で
  後から掛けられる一つの係数にまとめる。

## 5. 目標選択と分担

- 明示`assignedTargets`を最優先する。
- hunt／CAS／strikeは任務対象を最優先し、RAVENへ横滑りしない。
- CAP／SCREEN／ESCORT／TOP COVERは、守備点へ近いRAVEN、通常僚機、
  戦闘支援ARCAを脅威候補にする。
- 二機編隊は同じ対象へ完全重複させず、近い二候補がいる場合はslotで分担する。
- 一度選んだ生存目標は短時間保持し、別候補が明確に有利な場合だけ変更する。
- HALOなど非戦闘支援機は、`assignedTargets`またはhuntで明示された敵だけが狙う。

## 6. INTERCEPTOR状態機械

```text
VECTOR / REATTACK
    -> 距離短縮・高速進入
    -> 目標を追い越す、または最接近後に開距離へ転じる
EGRESS
    -> 現在の進行方向へ4〜7秒離脱
    -> 1.2〜2.0kmの再進入間隔を作る
REATTACK
    -> 目標の予測位置へ旋回
```

- 単純な一定秒数だけでなく「最接近距離」「開距離」「目標が後方」の組合せで
  オーバーシュートを判定する。
- 地形回避、ストール回復、ミサイルbreakは常に上位優先とする。
- break終了後は保存したpurpose状態へ戻り、旧engageRangeへ落とさない。

## 8. 禁止事項

- 索敵距離を延ばす代わりに全敵を同時にRAVENへ殺到させない。
- ARCAを赤TGT化、ランク必須化しない。
- 高性能機や増援数を無計画に増やさない。
- 武器射程、ロック時間、旋回性能を索敵AIの都合で水増ししない。
- マップ形状・地形配置には触れない。

## 9. 実装後シミュレーション／横断監査

`tools/simulate_enemy_air_ai_engagement.mjs`で18kmから接近する220／300／
420m/sの三条件を計算した。防御purposeは探知後コミットまで14.8〜36.4秒の
追跡窓を持ち、索敵と迎撃開始が同時になる旧挙動を解消した。INTERCEPTORは
300m/s換算で最短1.05km、最長1.95kmの離隔を作り、1.5kmの再進入条件を
3.5〜6.5秒の窓内で横切る。

`tools/check_sera_enemy_ai_watchdog_e2e.mjs`はM01〜M20を個別起動し、現時点で
174機の固定翼についてpurpose、sensor、contact、aim、有限座標、station、
INTERCEPTOR phaseを横断確認してPASSした。M04の艦隊CAPはRAVENが艦隊から
約19km離れている時に正しく未探知／艦隊上空待機となり、広域索敵化が
全戦場での透視・無限追撃にはなっていない。

追撃経路は近距離と遠距離を分離した。600m以内では従来どおり目標後方へ
収束し、3.4km以遠では最大520mの進行方向先読みへ連続補間する。SCREEN／
ESCORT／CAP／TOP COVERはさらに守備対象側へ割り込み、遠距離の純追尾と
護衛対象の後追いを避ける。旋回率、速度、武器射程、ロック時間は変更しない。

既存の17本のミッションE2E（M01〜M03、M07〜M20）は8340番の実配信で
全PASSした。M04〜M06は専用payload検査と横断watchdogで確認し、全20
payload検査、`registry_gate`（19 tables、loss 0）、20 payloadのinline同期、
radio canon（20 missions／311 strings）、`git diff --check`もPASSした。
8340番の配信ファイルとローカル`index.html`は4,082,620 bytes、SHA-256
`92048d3838ce496b0cdf0daf77cd7b8374798009958c1d41e79f6c262a671825`で一致した。
