# GIBOR闇ルート最終戦 — CROWN / LARK 戦闘アルゴリズム・耐久規約

> [GIBOR最終戦正本](./00_gibor_crown_lark_finale.md)

**状態:** M20 GIBOR闇ルートのボス戦実装補足正本  
**更新日:** 2026-08-08  
**対象:** `CROWN` / `LARK` の戦闘挙動・耐久・実装方式

---

# 0. 絶対規約

1. **NPC戦闘に機械学習、生成AI、外部AIモデル、推論APIを使用しない。**
2. CROWN / LARK の強さは、既存のゲーム内飛行・戦闘ロジックを拡張した**手書きの決定論的／ルールベース戦闘アルゴリズム**で作る。
3. 「ボスだから回避率を不正に上げる」だけにはしない。位置、角度、距離、速度、相方の状態を読んで行動を切り替える。
4. **HPは通常戦闘機より高くする。** ボス戦なので、通常エースと同じ一〜二発で終わらない耐久を持たせる。
5. ただし完全な弾丸スポンジにはしない。耐久増加とアルゴリズム強化の両方で難度を作る。
6. CROWNとLARKは別々の人格・役割を持つ。二機が同じロジックでプレイヤーを追うだけの戦闘は禁止する。
7. 通常難易度でも初見クリア可能な範囲にし、ACEでは挟撃・射撃判断・回避継続を強化する。
8. TGT化後は無線0というv0.15最終戦規約を維持する。戦術の違いは台詞ではなく飛び方だけで示す。

---

# 1. 実装方式

CROWN / LARK 専用ロジックは、既存敵機アルゴリズムの上に「ボス戦用状態遷移」を追加する形を基本とする。

使用してよい入力:

- RAVENとの距離
- RAVENへの相対方位
- RAVENの速度
- RAVENの旋回方向
- RAVENが現在どちらをロックしているか
- 自機HP
- 相方HP
- 相方とRAVENの距離
- ミサイル警報
- 最終発射からの経過時間
- 地形・高度の安全範囲

使用しないもの:

- 機械学習モデル
- プレイヤー操作履歴を学習する仕組み
- 外部推論サービス
- LLM
- ニューラルネット
- ランダムに命中率だけを上げる不透明な補正

挙動は再現可能で、デバッグ時に「なぜその行動を選んだか」を状態として確認できるものにする。

---

# 2. CROWN — 主攻・読み合い担当

CROWNはRAVENへ飛び方を教えた元隊長であり、二機のうち高技能側。

役割:

- 主攻
- RAVENの注意を引く
- 正面から無駄撃ちしない
- RAVENがLARKを追う時に背後へ入る
- RAVENがCROWNを追い続ける時は、LARK側へ射線を渡す

基本状態:

```text
PRESSURE
  RAVENへ圧力を掛ける

BREAK
  ミサイル警報時に回避

DRAG
  RAVENをLARKの射線へ引く

REVERSE
  RAVENがオーバーシュートした時だけ攻守反転

SUPPORT_LARK
  LARKが追われ続けている時に割り込む

LAST_ONE
  LARK喪失後の単独最終戦
```

CROWNは常にRAVENの背後を魔法のように取らない。速度差、旋回半径、攻撃角度を満たした時だけ攻撃姿勢へ入る。

## 耐久

初期調整目安:

```text
通常戦闘機 = 1.0
通常ネームド = 1.3〜1.6
CROWN = 2.5〜3.0
```

最終値は実機プレイテストで決める。

CROWNは二機のうち高耐久側。ただしHPが高いだけでなく、回避と位置取りで長く生存することを優先する。

---

# 3. LARK — 援護・挟撃担当

LARKはCROWNより単独戦闘力を低くする。ただし二機戦では非常に危険にする。

役割:

- 援護
- 横槍
- 挟撃
- CROWNへの追尾を妨害
- RAVENが一機へ固執した時に射線へ入る

基本状態:

```text
SCREEN
  CROWNとRAVENの間へ割り込む

OFFSET
  RAVENの正面を避けて側面位置を維持

PUNISH_LOCK
  RAVENがCROWNへ長時間ロックを固定した時に攻撃

BREAK
  被ロック・被射撃時に回避

SUPPORT_CROWN
  CROWNのHP低下時に積極的にRAVENを引き剥がす

LAST_ONE
  CROWN喪失後も逃げずに単独戦闘
```

LARKは常時ミサイルを撃たず、RAVENがCROWNへ集中した瞬間を狙う。

## 耐久

初期調整目安:

```text
LARK = 1.8〜2.3
```

CROWNより低くするが、通常ネームドより明確に高い。

CROWNを先に撃墜した場合でも、残ったLARKが通常機のように簡単に処理されない耐久を持つ。

---

# 4. 二機連携

二機が生存している間は、両方が同時にRAVENの真後ろへ並ぶ挙動を避ける。

基本原則:

```text
一機が主攻
もう一機が側面・後方候補位置
↓
RAVENが主攻側へ固執
↓
援護側が攻撃
↓
RAVENが援護側へ向く
↓
役割を交換
```

これを高頻度で瞬間切替すると不自然なので、状態維持時間とクールダウンを持たせる。

禁止:

- 二機が全く同じ航路を飛ぶ
- 二機が同時に同一角度からミサイルを連射するだけ
- 瞬間旋回
- 無限加速
- プレイヤー入力を直接読むチート
- ロックされる前にロック入力そのものを検知する
- 射線外からの命中判定

---

# 5. 撃墜順による変化

## LARK先行撃墜

CROWNは無言のまま`LAST_ONE`へ移行。

- 攻撃頻度を少し上げる
- 単独なので挟撃は消える
- 高耐久と読み合いで勝負する
- 怒り演出の無線は入れない

## CROWN先行撃墜

LARKも無言のまま`LAST_ONE`へ移行。

- 逃走しない
- CROWNほど高度な読み合いはしない
- 旋回・回避・短い攻撃窓を重視
- HPは残量をそのまま維持し、第二形態として全回復はしない

---

# 6. 難易度差

HPだけで難易度差を作らない。

```text
NORMAL
- 発射判断をやや遅くする
- 挟撃成立後にも攻撃猶予を持たせる
- 回避継続時間を短めにする

HARD
- 標準ボスロジック
- 役割交換を早める
- プレイヤーの一機集中をより積極的に咎める

ACE
- 射撃角度の判断を厳密化
- CROWN / LARKの役割交換を最適化
- ミサイルを浪費しにくくする
- 低HP時でも単純逃走せず、反撃機会を探す
```

耐久倍率も難易度に応じて微調整してよいが、ACEだけ極端なHPにしない。

---

# 7. 実装・検収項目

実装時に最低限確認する。

- AI/機械学習モデルを導入していない
- CROWNとLARKが異なる状態遷移を持つ
- 二機が役割交換できる
- RAVENが一機へ固執するともう一機が有利になる
- CROWN / LARKのHPが通常ネームドより高い
- 弾丸スポンジだけの難しさになっていない
- どちらを先に倒しても進行可能
- 一機撃墜後に残機が無言で戦闘継続
- TGT化後の無線0
- 不正な瞬間旋回・無限加速・射線外命中なし
- NORMALで初見クリア可能
- HARD / ACEでアルゴリズム差が体感できる
- pageerror 0

# 8. 用語規約

今後、設計書でこのボス挙動を説明する際は、曖昧な「AIを強くする」という表現を避ける。

推奨:

```text
NPC戦闘アルゴリズムを強化する
ボス専用の状態遷移を持たせる
CROWN / LARKの連携ロジックを実装する
```

非推奨:

```text
AIを学習させる
AIモデルを導入する
生成AIで敵を動かす
```

本ゲームのNPC戦闘は、手書きのゲームロジックで実装する。
