# 1. 絶対に変えない三色規約

本作のマップ、レーダー、HUD上の接触表示は、機種・陣営名・エース名ではなく、プレイヤーにとっての関係とミッション指定だけで色を決める。

| 色 | 意味 | 攻撃・ロック | ミッションクリア |
|---|---|---|---|
| **赤** | `TGT`。ミッション指定目標 | 可能 | 原則として撃破・処理が必要 |
| **白** | 非TGT敵。普通の敵だが任務上の必須目標ではない | 可能。敵も攻撃する | 無視してもよい |
| **青** | 味方・準友軍 | 不可 | 護衛契約が明示された場合だけ成否に関係 |

判定は必ず次の一か所に集約する。

```text
friendly配列にいる                 → BLUE
敵で isTgtEntry(contact) が true   → RED
敵で isTgtEntry(contact) が false  → WHITE
```

## 1.1 色を変えてはいけない状態

選択、ロック完了、マルチロック、ネームド、エース、ARCA、ステルス機、警報中であっても、接触の所属色は変えない。

- 白い敵を選択しても黄色や緑にはしない。
- 選択は枠の二重化、点滅、太さ、名前表示で示す。
- ロック完了は内側の菱形、収束線、点滅で示す。
- ミサイル警報でHUD全体が赤くなっても、白敵と青味方の接触色は維持する。
- 機体別・エース別の `radarColor` は、マップ上の敵味方識別には使用しない。
- `radarColor` を残す場合も、デバッグ、演出、曳光弾、爆発、機体塗装の用途だけに限定する。

## 1.2 適用範囲

三色規約は次のすべてへ同時に適用する。

- レーダーのブリップ
- 画面内の航空機・艦艇・地上目標マーカー
- 画面外方向矢印
- 選択中ターゲット枠
- 通常ロック・マルチロック枠
- 名前・距離表示
- デバッグ用HUDプローブ

`TGT`という文字は赤い指定目標だけに表示する。白敵と青味方には絶対に表示しない。

# 2. ARCAの固定関係

| キャンペーン | 時期 | 配列・経路 | 色 | 攻撃性 | TGT |
|---|---|---|---|---|---|
| セラ編 | 序盤 | 友軍スポーン／`friendlies[]` | 青 | エレム敵を攻撃、プレイヤーを攻撃しない | なし |
| セラ編 | 中盤以降 | 敵スポーン／`enemies[]` | 白 | プレイヤーを通常攻撃 | 常にfalse |
| エレム編 | 全編 | 敵スポーン／`enemies[]` | 白 | プレイヤーを通常攻撃 | 常にfalse |

ARCAが赤くなることはない。F-3を含むすべての敵対ARCA機は、攻撃可能で攻撃もしてくる白い雑魚敵である。

## 2.1 セラ序盤

- Typhoon、Rafale、Gripenを準友軍として使用できる。
- 命令できる僚機にはしない。
- ARCA機の生存、全滅、撃墜数を後続へ保存しない。
- F-3は研究機なので序盤には出さない。

## 2.2 セラ中盤以降

- ARCAは白い非TGT敵として登場する。
- ロックオン、ミサイル、機銃、撃墜が可能。
- ARCA側も機銃とミサイルでプレイヤーを攻撃する。
- 無視して本来の赤TGTだけを処理してもクリア可能。

## 2.3 エレム全編

- 最初の任務から白い非TGT敵。
- 中盤でARCAがセラとも敵対した後も、エレム側のゲーム上の関係は変えない。

# 3. ARCAをミッションへ影響させない契約

ARCAは戦闘には影響するが、ミッション構造と分岐には影響させない。

```text
faction: "arca"
tgt: false
rankNeutral: true
persistent: false
canAttackPlayer: true
canBeDestroyed: true
```

## 3.1 得点

- ARCA撃墜は通常の非TGT撃墜ボーナスを与えてよい。
- `bonusKills`へ加算してよい。
- ただしランクの母数 `rankStats.spawnedValue` へは加えない。
- ランクの分子 `rankStats.playerKillValue` へも加えない。
- したがってARCAを一機も倒さなくてもSランク可能で、ARCAを倒してもS条件そのものは緩くならない。

既存の全非TGT敵をランク中立にはしない。`rankNeutral: true`を持つARCAなど、明示した妨害敵だけを対象にする。

## 3.2 AI標的

敵対ARCAは次を攻撃できる。

- プレイヤー
- 通常友軍戦闘機
- ミッション成否に直結しない戦闘ユニット

敵対ARCAは次を攻撃しない。

- 護衛失敗条件の輸送機、病院船、避難車列
- 生存・破壊によってフェーズが進む主目標
- 出現直後に攻撃可能な距離の護衛対象

ARCAの攻撃だけで任務失敗、TGT消失、Sランク不能が起きないようにする。

# 4. ブランチ方針

実装は古いストーリーブランチ上では行わない。

1. 最新`main`から `chatgpt/reboot-air-iff-foundation` を作る。
2. `chatgpt/f3-aircraft`からF-3本体と上位機バランスペイロードだけをレビューして移す。
3. `chatgpt/fighter-roster-expansion`は現時点で`main`と同一なので、実装基準には使わない。
4. 各便を1コミットにし、次便は前便の検収後に積む。
5. `index.html`へ直接並列書き込みせず、登録追加はpayload方式を優先する。
6. HUD、スコア、友軍配列など本体変更が必要な便だけ、単独で`index.html`を変更する。

# 8. 最初に着手する範囲

最初の実装ターンでは第1便だけを行う。第1便で現行の挙動とプローブを固定し、第2〜第5便で三色とランク計算を完成させる。ARCA機や新機体をミッションへ置くのは、その後にする。

理由は、機体を先に増やすと、赤・白・青、TGT、ロック、ランク母数の不整合を全機へ広げてしまうためである。まず「色と役割の意味」を本体に一度だけ実装し、その契約へ各機体とミッションを接続する。
