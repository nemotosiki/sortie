# 地形起伏の実装方式（第7便・設計）

**決定日**: 2026-07-28
**設計**: Fable 5（architect）
**位置づけ**: ロードマップ第7便「地形起伏」の設計。本体改修が要るためペイロードでは届かず、
実装はこちら（Claude側）で行う。

---

## 結論

**マップごとのハイトフィールド（Float32Array格子）から単一の変位メッシュを生成し、
`surfaceHeightAt` の初期値 `let height = 0` をO(1)の格子バリセントリック補間
`heightfieldAt(x,z)` に差し替える。既存の山＝レイキャストはそのまま上に残す。**

峡谷・市街地の地面・全域の起伏はすべてこの1枚で作り、山メッシュ機構は
「地形の上のランドマーク」に役割を限定する。

---

## なぜこの方式か

### 契約の実体を取り違えない
`surfaceHeightAt` に地上ユニットの設置（誤差0.0000）とヘリの高度維持が依存しているが、
**守るべき契約は「サンプラーの返り値が描画面と一致すること」であって「レイキャストという実装」ではない。**
メッシュを手組みして三角形分割をサンプラーと共有すれば、補間結果は描画三角形そのものになり
誤差は構造的に0。しかもO(1)（配列2読み＋lerp）でレイキャストより桁違いに安い。

Unity Terrain / Bullet `btHeightfieldTerrainShape` と同じ業界標準構成。地形の高さ取得に
レイキャストを使い続ける方式は標準的に避けられている。**コード内のコメント自身が
「raycastは高いから車列はbakeした」と証言している**（index.html 21249-21266行）。

### 山メッシュ拡張案を採らない理由
1. 凸型の変位コーンでは**峡谷（凹地形）が原理的に作れない**。現 glacierCanyon の
   corridor＝壁2列ハックが限界で、谷底が海のまま
2. 全域起伏をコーンの重ね合わせで作ると `surfaceHeightAt` の三角形数がクエリコストに直結して
   増え続ける（ホットパス）。ハイトフィールドなら地形が何kmあってもクエリはO(1)

### ノイズ関数の直接評価を採らない理由
メッシュは離散化されるので頂点間で関数値 ≠ 描画面となり、0.0000の設置精度が壊れる。
**格子補間だけがメッシュと厳密一致する。**

## 接続点は3つだけ

### 1. サンプラー
- `surfaceHeightAt`（21208行）/ `surfaceTopAt`（21233行）:
  `let height = 0` → `let height = heightfieldAt(x, z)`。**山ループは無変更**
- `world.heightfield = { x0, z0, cell, size, data }` を `createWorld` の返却レコードに追加
- **プリセットに定義が無ければ `null` → 0を返す＝既存8マップはビット単位で不変。**
  導入はマップ単位で段階的にできる

### 2. プレイヤー墜落判定
18906行の `y <= 4` と 18911行の山シリンダー判定。海面固定の `4` を
`Math.max(4, heightfieldAt(x,z) + 4)` に。1フレーム+1回のO(1)呼び出しのみ。

### 3. メッシュ生成
`createWorld` 内で格子から `BufferGeometry` を手組みする。
- **`PlaneGeometry` を使わない**（三角形分割を自前で持つことがサンプラーとの一致保証）
- 高さ/傾斜で頂点カラー（既存 `terrainStyle` パレット流用）
- `keepGeometry` / `keepMaterial` / `addRoot` へ登録 → **`disposeWorld` は無改修で回収できる**

## 飛べる峡谷の数値（glacierCanyon）

設計速度 180〜250 m/s（320 m/s は峡谷では減速する前提）、旋回半径 ~1km として:

| 項目 | 数値 | 根拠 |
|---|---|---|
| 谷幅（床・壁間） | **350〜500m**（直線部） | 2秒の修正遅れで生じる横ずれ（250m/s × 2s × sin10° ≈ 90m）の4〜5倍が「怖いが公平」の下限 |
| 中心線の曲率半径 | **≥ 1200m** | 最大旋回半径の1.5倍。S字2〜3個、90°ブラインドコーナー禁止 |
| 前方視程 | **常に1.5km以上** | 3秒先が見える |
| 稜線高（谷床から） | **+350〜500m** | 現 glacierCanyon の最高峰561mと整合。壁勾配60〜75° |
| 長さ | **8km以上** | 200〜250 m/s で30〜40秒のラン。±9kmのマップに斜め/S字で10〜14km収まる |
| 進入用の直線 | 1.5〜2km | |
| 谷床 | 海抜 +30〜60m、±15mの緩い起伏 | AGL感を出す。0m以下に彫った部分は既存の海面プレーンがそのまま水になり、海岸線も自動で成立 |

格子セル約40mなら2〜3セルで壁が立ち、60〜75°の勾配を表現できる（70mセルだと60°が上限気味）。

## 性能予算

| 項目 | 見積もり |
|---|---|
| geometries | **+1/マップ**（39→40） |
| draw call | **+1**（分割せず1枚で開始。カリングが要るなら4×4分割でも+16） |
| 頂点数（緩起伏マップ） | 256²格子（±9kmで約70mセル）→ 約66k頂点 / 131k三角形 |
| 頂点数（峡谷マップ） | 512²格子（約39mセル）→ 約263k頂点 / 524k三角形 |
| GPUメモリ | +3〜16MB。高さ配列は256KB〜1MB |
| `surfaceHeightAt` | **悪化しない。** 追加は格子補間1回（サブµs）。山が範囲内のクエリは従来と同一＋ε |

`updateMatrixWorld` の回数は不変、`debug.surfaceSamples()` の意味も不変。

### ★実測で裏取り済み（2026-07-28）

見積もりの「60fpsに影響しない見込み」は**実機で確認した**。RTX 4070 / ANGLE D3D11、
m01のミッション中（敵が出現・行動中）、各条件260フレームをサンプル:

| 条件 | 中央値 | 平均 | 95%ile | fps(中央値) |
|---|---|---|---|---|
| ベースライン | 16.70ms | 19.95ms | 33.40ms | 59.9 |
| 256²格子（13.1万三角形） | 16.70ms | 20.97ms | 33.40ms | 59.9 |
| 512²格子（52.4万三角形） | 16.70ms | 20.27ms | 33.40ms | 59.9 |

**3条件とも中央値・95%ileが同一。** 静的メッシュ1枚の追加コストは測定ノイズに埋もれる。
512²でも 60fps を守れる。ボトルネックは地形メッシュではない。

**計測手法の注意**: 最初1プロセスで3条件を連続実行したところ2条件目でクラッシュし、
ベースラインが逆に遅く出た（平均41ms / p95 150ms＝メッシュ条件より遅いという逆転）。
条件間のGPU/プロセス干渉。**条件ごとに新規ブラウザプロセスを起動**して解消。
上表は分離後の値。今後この種の測定は必ずプロセスを分けること。

なお `--use-gl=angle --use-angle=swiftshader`（ソフトウェアレンダリング）で走っている既存の
`verify_*.mjs` は**性能測定には使えない**。実GPUを使うには `--ignore-gpu-blocklist
--disable-gpu-sandbox` で起動し、`WEBGL_debug_renderer_info` で実GPUを掴んだか確認する。

## 実装の最初の5手順

1. `heightfieldAt(x,z)` サンプラーと `world.heightfield` レコードを追加（null時0）。
   `surfaceHeightAt` / `surfaceTopAt` / プレイヤー床判定の3点に接続。
   **全既存マップで挙動不変を確認**
2. `createWorld` にメッシュ生成器を実装（格子→手組み `BufferGeometry`、三角形分割共有、
   頂点カラー、資源4配列に登録）
3. **glacierCanyon のフィールドを最初に作る**（台地ベース+450m、S字峡谷: 床+40m / 幅400m /
   稜線+450m / 長さ約9km / 曲率半径≥1200m）。既存 corridor 山との重なりを整理
4. 検証ゲート: 新メッシュへの実レイキャスト vs `heightfieldAt` の全域一致（期待0.0000）、
   地上ユニット設置誤差、14×14起伏サーベイ再実行、`surfaceSamples` 非増加
5. fps実測と峡谷の試験飛行 → 合格後、他マップへ1枚ずつ展開
   （各マップのミッション地上配置を個別に確認しながら）

## リスクと未確認事項

- ~~**ターゲットGPUが不明**~~ → **解消（2026-07-28実測）。** RTX 4070 で512²でも60fps。
  上の性能予算欄を参照。**ただし測ったのはこの1台だけ**なので、弱いiGPUでの動作を保証する
  ものではない。そこが要件になったら256²（70mセル・壁60°）に落とす余地は残っている
- **既存ミッションのAI機・スクリプト経路の固定高度。** 地形を盛ったマップでは、固定yで飛ぶ
  敵機・爆撃機が新しい稜線に刺さらないか監査が要る（地上ユニット・ヘリ・車列は
  `surfaceHeightAt` 経由で自動追従するので無事）。12438行の「GLACIER SHIELD」は
  山の位置参照なので不変
- **既存マップに起伏を入れると、ミッション定義は不変でも体験の難度は変わる。**
  「既存ミッションは追加のみ」の文言上はセーフだが、意図の確認が要る。
  授権済み座標（車列道路・基地）周辺は平坦に保って作るのが安全
