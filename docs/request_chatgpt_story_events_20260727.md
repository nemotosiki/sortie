## 2. 今回作るもの — R06 ↔ A15 の因果ペア（最優先6組のうちの1組）

設計文書の「X字構造」の実装第1弾です。

| ミッション | 何を足すか |
|---|---|
| **r06** GLACIER SHIELD | 電力網リレー3基を**任意目標**として追加。撃つかどうかはプレイヤーの自由 |
| **m-city** CITY LIGHTS | r06 でリレーを撃った数に応じて、街が区画ごとに消灯する |

### なぜ「任意」なのか（ここが今回の肝です）

必須目標にすると、m-city で街が消えるのは「そういうストーリーだから」でしかありません。
プレイヤーに選択肢がない以上、罪にもなりません。

**任意にすると意味が反転します:**
- 撃った → m-city で街が落ちる。**自分が落とした**
- 撃たなかった → 照明が生きている。**ただしその電力で動く敵防空も健在**

このゲームのテーマは「両方とも正義で、両方とも悪」です。
それはプレイヤーが実際に手を汚せて初めて成立します。

**重要**: 撃たなかった場合に「何も起きない」だけだと、撃たない選択が無価値になります。
**両方の選択に結果を用意してください。**

## 3. 使える仕組み（すべて実装済み・実測確認済み）

### ① 任意目標 = `tgt: false`

ウェーブ定義にも `groundUnits` の各エントリにも付けられます。
- `tgt: true`（既定）… 撃破必須。`totalTargets` に数えられる
- `tgt: false` … 撃破しなくてもクリアできる。倒せばスコアには入る

（`isTgtEntry` が index.html 4215行、`groundUnits` への適用が 9332行）

### ② 選択の記録 = `mark`（今日こちらで実装しました。`3a44d0f`）

**地上ユニットに `mark: "文字列"` を付けると、それを破壊したときにカウントされます。**
ミッションクリア時に、そのミッションの記録（localStorage）に保存されます。

読み出しは:
```js
window.__game.marksTaken("r06", "gridRelay")   // → 撃った数（0〜3）
```
ペイロードのコンテキストからも `ctx.marksTaken(missionKey, mark)` で同じものが読めます。

- 一度も飛んでいないミッションは **0** を返します（＝「撃たなかった」と同じ扱い。意図的です）
- リトライすると上書きされます（最後に飛んだときの状態が残る）
- チェックポイント再開をまたいでも残ります

検証用フック: `debug.markProbe()` で現在の状況が見え、`debug.forceMark(mark, n)` で
実際にユニットを破壊せずにマークを立てられます。

### ③ 時間差の投入 = `delay`

ウェーブ定義に `delay: 秒数` を付けると、その秒数後に投入されます。
`concurrent: true` と組み合わせられます。

### ④ 無線

`triggerRadioLine(speaker, text, priority, id)` で流せます。
話者は `command` / `wingman` / `enemy` の3系統、優先度キューとクールダウンがあります。

## 4. 具体的な仕様

### 4-1. r06 に電力網リレー3基を追加

- 既存の地上目標4基（samSite×2 / radarSite×1 / commandPost×1）は**そのまま**
- 新たに**電力網リレー3基**を追加する。既存の `GROUND_TYPES` から適切なものを選ぶか、
  必要なら新種を1つ追加してよい（`ctx.addGroundType`）
- **3基すべてに `tgt: false` と `mark: "gridRelay"` を付ける**
- 位置は既存4基と離し、プレイヤーが「寄り道して撃つ」形になるようにする
- ブリーフィング文は**変更しない**（民間併用だと事前に知らせない）
- **1基撃つごとに無線を1本**流す。設計文書の案:
  ```
  NFF CONTROL: 「GRID-C relay offline」
  NFF CONTROL: 「GRID-B relay offline」
  NFF CONTROL: 「GRID-A relay offline」
  ```
  日本語で書いてよいが、`GRID-A/B/C` という区画名は**m-city 側と一字一句同じにする**こと。
  これが対応関係の唯一の手がかりになります
- 撃った後に、**軍用回線ではないことを匂わせる無線を1本だけ**入れる。
  説明しすぎないこと（例: 味方が一瞬黙ってから「……了解」とだけ言う、程度）

### 4-2. m-city で r06 の選択に応じて変える

- `ctx.marksTaken("r06", "gridRelay")` で 0〜3 を読む
- **撃った数だけ、街の区画が消灯していく無線を流す**。区画名は r06 と同じ `GRID-A/B/C`
  ```
  CITY GRID: 「GRID-C、電力喪失」
  CITY GRID: 「GRID-B、医療回線停止」
  CITY GRID: 「GRID-A、応答なし」
  ```
- **敵爆撃機を撃墜するたびに1区画落ちる**形にする。
  つまり「撃墜成功」と「街が死ぬ」が同じ瞬間に起きる。これが狙いです
- 最後の敵を倒したとき:
  ```
  COMMAND: 「敵航空戦力、全滅」
  CITY GRID: 「市内全区画、消灯」
  COMMAND: 「防衛任務成功」
  ```
  この「成功」という言葉が最も残酷な無線になります
- **撃たなかった場合（marksTaken が 0）**: 街は生きている。
  代わりに、**その電力で動いている敵の防空が健在**という形で難易度に反映する
  （例: 対空砲やSAMを追加する、あるいは敵ウェーブを1つ増やす）。
  無線も別のものにすること。「街の明かりが見える」ことがプレイヤーに伝わるように
- 部分的に撃った場合（1〜2基）は、その数だけ区画が落ちる

### 4-3. 実装上の原則（設計文書 §7 より）

- **重大な無線はプレイヤーの操作から1秒以内に流す。**
  最後の敵を撃墜 → 爆発を見る → 直後に区画消灯。
  頭ではなく指と記憶が因果を結びます
- **1ミッションに入れる大きな意味は1つに絞る。**
  r06 = 選択、m-city = 不可逆性。それ以外の意味を足さない
- 説明的な長台詞を書かない。プレイヤーに考える暇を与えず、また撃たせる

## 6. 検収基準

こちらで実測します。

- `index.html?payloads=...` で起動し、コンソールエラーゼロ
- 全40ミッションが起動でき、`missionKeys()` が40本のまま
- r06 の地上目標が 4→7 基になり、うち3基が `tgt: false`
- r06 の `totalTargets` が**増えていない**こと（任意目標なので必須数は変わらない）
- `debug.forceMark` を使わず、実際にリレー3基を破壊して
  `markProbe().sortie.gridRelay === 3` になること
- r06 をクリア後、`marksTaken("r06","gridRelay")` が撃った数を返すこと
- m-city を 0基/3基 の両方の状態で起動し、**無線の内容が変わること**
- 0基のとき、m-city に何らかの追加の手応え（敵防空など）があること
- 既存5本（m-glacier, m-night, m-convoy, m-train, m-desert）の地上目標数が不変
  （4/11/1/2/12）
- `node tools/registry_gate.mjs` が通ること
- `git diff` で `index.html` にハンクがゼロ

- r06 のリレー3基の座標と、そこを選んだ理由
- 撃った場合／撃たなかった場合それぞれの m-city の無線全文
